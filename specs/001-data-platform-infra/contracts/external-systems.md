# Contract: External Systems Interface

Interface through which external systems consume the processed data over the internet (FR-013).
Decisions: D-016, D-017, D-019, D-026, D-028 in [research.md](../research.md).

## Endpoint

| Item | Value |
|---|---|
| Protocol | Trino client protocol over HTTPS (Trino JDBC, Trino Python client, Trino CLI) |
| Host | DNS name of the platform NLB; it changes when the cluster is recreated and is sent to each external system |
| Port | Dedicated Trino port on the `Gateway` (number set at implementation) |
| TLS | Self-signed certificate generated by Terraform (D-028); TLS is not terminated by the `Gateway` |
| Certificate verification | The client trusts the platform certificate and verifies the certificate authority only (JDBC `SSLVerification=CA`), because the host name changes |

## Authentication

- One Trino user and password per external system (password file authentication).
- Credentials are delivered to each system outside the repository (constitution IV).
- A request without valid credentials is rejected by Trino (FR-013).

## Authorization

- Each external system user can read only the schemas and tables granted in the Trino access
  rules (file-based access control, D-026); in principle, the gold layer only.
- Sensitive columns are masked or hidden by the rules (FR-006).

## Usage expectations

- Read-only SQL queries.
- Data downloaded is charged as AWS data transfer out (US$ 0.09/GB, first 10 TB/month).
